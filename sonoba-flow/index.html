図はいつも、会議のあと

PROBLEM

業務改善もDXも、いまの業務を目に見える形にするところから始まります。ところが多くの現場では、その業務フロー図づくりだけが、いまだに人の手に残っています。

図ができるまで数日かかる

ヒアリングの内容を担当者が持ち帰り、あとから図に起こすため、完成までに日数がかかります。

認識のズレで会議がもう一度

できあがった図を見せたら食い違っていた。確認のためだけの会議が、また1回必要になります。

AIに描かせても間に合わない

文字起こしから図を作る方法も広がっていますが、図ができるのは会議のあと。業務を知っている参加者は、もう解散しています。

その場で描いて、その場で直す

SERVICE

その場フローは、会議の音声から業務に関係する発言だけを選び出し、担当部署ごとのレーンに分かれた業務フロー図（スイムレーン図）をリアルタイムに描いていきます。図は会議の進行に合わせて更新され、参加者がその場で確認して、その場で直せます。

業務の話だけを拾う

雑談や愚痴は図に反映しません。発言ごとに「業務プロセスに関する内容か」を判定します。

分岐も差し込みも訂正も

「在庫がなかった場合は…」のような条件分岐、「出荷の前に…」のような手順の差し込み、「さっきの担当は違って…」という訂正も、会話の流れのまま反映します。

「要確認」として残す

担当者が明言されていない手順や、根拠の弱い手順は破線で表示します。会議中に確認すべき事項として、一覧にも出します。

draw.io 形式で出力

生成された図は draw.io でそのまま編集でき、.drawio ファイルや PNG で保存できます。AIが下書きを作り、人が仕上げる使い方を想定しています。

オンライン会議にも対応

マイクのほか、Web会議のタブ音声も入力にできます。対面でも、画面越しでも使えます。

会議のスピードに追いつく

判定を担うモデルが軽いため、話している最中に図が伸びていきます。会議を止めて待つ必要がありません。

作るAIと、疑うAIを分ける

ARCHITECTURE

生成AIに図を描かせると、言っていない手順をもっともらしく補ってしまいます。その場フローは、文章を作る役割と、それを疑う役割を別のモデルに分けました。

  1. 1
    Jev

    業務の話かを判定する

    発言ごとに「業務の話か」と「図に何をすべきか（追加／修正／削除／なし）」の2点を、確率で判定します。基準を超えた発言だけが次へ進みます。

  2. 2
    LLM

    操作に組み立てる

    通った発言を、「誰が・何をする・どこにつなぐ」という、図に対する具体的な操作に変換します。

  3. 3
    Jev

    1件ずつ疑う

    その操作を1件ずつ、本当に発言されたか、既存の手順と重複していないか、担当は誰か、の3点で再検証します。

  4. 4
    プログラム

    図に反映する

    検証を通過した操作だけを、プログラムが決められた手順どおりに draw.io の図へ反映します。確率が足りなかった操作は破棄するか、「要確認」として残します。

使う場面と、残るもの

USE CASE

こんな場面で使えます

  • 業務改善・BPR・システム導入前の、現状業務のヒアリング
  • 業務の引き継ぎ、マニュアル整備、内部統制文書の作成
  • コンサルタントや情報システム部門による、要件定義ワークショップ

終わったときに残るもの

  • 参加者が確認済みの、業務フロー図の下書き
  • 会議の中で解消できた、認識のズレ
  • 決めきれなかったことが並んだ「要確認」の一覧
  • draw.io でそのまま編集できるファイル

業務改善の担当者が、図を描く作業と、確認のための会議から解放されます。空いた時間は、改善策そのものを考えることに使えます。

Jevとは

MODEL

Jev（ジェブ）は、米 TypeSafe AI 社が2026年9月に公開した System One モデルです。

一般的なLLMのように文章を順に生成するのではなく、「はい／いいえ」「選択肢」「段階評価」といった、あらかじめ型を決めた問いに対して、確率つきの構造化データで答えることに特化しています。

文章を作らないぶん速く、判断の確からしさが数値で返ります。その場フローは、この性質を「疑う側」に使っています。
